# All Data Inside APK Configured PERMANENTLY at Root Level

**Requirement:** When we configure all data inside APK, it has to be permanent at root level.

**Solution:** All APK data configuration lives at root level permanently, bundled into APK.

---

## How Permanent Root Config Works

### 1. Config Priority (Permanent First)

`mobile/src/js/live_db.js` loads in this order:

1. **ROOT_CONFIG from `mobile/src/js/root_config.js`** - Hardcoded from root `.env`, **permanent in APK**
   - Generated by `scripts/configure_root_apk.py --build` from root `.env`
   - `export const ROOT_CONFIG = {supabase_url, backend, is_live}`
   - `window.ORBIX_ROOT_CONFIG` global
   - This is inside APK JS bundle, cannot be lost

2. **`./root_config.json` bundled in dist/** - From root level, **permanent in APK**
   - Copied from `mobile/src/root_config.json` (generated from root)
   - Inside `dist/` which is bundled into APK assets

3. **`window.ORBIX_ROOT_CONFIG`** - Global from index.html, permanent

4. **localStorage** - User override via Settings ⚙️, saved locally

5. **`/api/database/config`** - API at root level, when running via FastAPI

So even if localStorage cleared, APK still has permanent root config from `root_config.js`.

### 2. Generation Flow (Permanent at Root)

```bash
# You set at root .env (permanent)
echo "DATABASE_BACKEND=supabase" >> .env
echo "SUPABASE_URL=https://xxx.supabase.co" >> .env
echo "SUPABASE_ANON_KEY=eyJ..." >> .env

# Script generates ALL configs at root level permanently
python scripts/configure_root_apk.py --build

# Generates:
# - database/apk_config.json at root (permanent, committed to GitHub)
# - database/root_manifest.json at root (manifest, permanent)
# - mobile/src/js/root_config.js (hardcoded in APK JS, permanent, committed)
# - mobile/src/root_config.json (bundled in dist, permanent)
# - mobile/public/root_config.json (PWA, permanent)
# - data/root_config.json at root (cache, permanent)
# - data/apk_build_info.json at root (build info)

# Build mobile copies root configs into dist/ (permanent inside APK)
./scripts/build_mobile.sh
# dist/ now contains:
# - root_config.json (from root)
# - apk_config.json (from database/ at root)
# - js/root_config.js (hardcoded)
# - data/mobile/ (initial data from root data/)

# Push -> GitHub Actions builds APK with permanent root config inside
git add database/apk_config.json mobile/src/js/root_config.js mobile/src/root_config.json
git commit -m "feat: permanent root config for APK live"
git push origin arena/6260349f-orbix
# Actions -> Download orbix-apk-debug -> APK has permanent root config inside, live online 24/7
```

## Usage - Make APK Permanent Live at Root Level

### In Codespace (All Files in GitHub, Not on Device)

```bash
# 1. Open Codespace from GitHub (all files already there, root level)

# 2. Check current root config (permanent)
python scripts/configure_root_apk.py --check

# 3. Init data/ at root level (permanent)
python scripts/configure_root_apk.py --init
# Creates data/ at root with orbix.sqlite3 + mobile/ + root_config.json

# 4. Configure Supabase PERMANENTLY at root level
# Option A: Interactive
python scripts/configure_root_apk.py --supabase
# Paste URL + anon key -> saves permanently at:
# - .env at root
# - database/apk_config.json at root (committed)
# - mobile/src/js/root_config.js (hardcoded in APK)

# Option B: Non-interactive (for CI)
python scripts/configure_root_apk.py --url https://xxx.supabase.co --anon-key eyJ... --service-key eyJ...

# 5. Verify permanent at root
cat database/apk_config.json
cat mobile/src/js/root_config.js
cat data/root_config.json
python scripts/configure_root_apk.py --check
# Should show: is_live true, backend supabase, LIVE ONLINE

# 6. Build mobile PWA with permanent root config inside
./scripts/build_mobile.sh
# Check dist contains permanent configs:
ls -lh mobile/dist/*.json mobile/dist/js/root_config.js
cat mobile/dist/root_config.json | grep -E "backend|is_live|supabase"

# 7. Run live in Codespace (24/7)
uvicorn orbix.api:app --host 0.0.0.0 --port 8000 --workers 1
# Open forwarded port 8000
# /api/database/config -> shows apk_config + is_live true
# /api/database/apk-config -> shows permanent APK config at root

# 8. Build APK with permanent root config inside (live 24/7)
git add database/apk_config.json database/root_manifest.json mobile/src/js/root_config.js mobile/src/root_config.json mobile/public/root_config.json
git commit -m "feat: permanent root config - all data inside APK at root level"
git push origin arena/6260349f-orbix
# GitHub Actions builds APK -> Download artifact orbix-apk-debug
# APK contains permanent root config, will be LIVE ONLINE 24/7 on phone
```

### On Phone - APK with Permanent Root Config

1. Download APK from GitHub Actions artifact (contains permanent root config from root level)
2. Install on Android
3. Open app:
   - Badge should already show `● LIVE ONLINE` blue if Supabase configured at root before build
   - Because `root_config.js` hardcoded in APK JS has Supabase URL from root `.env` permanently
4. If still offline (no Supabase at build time):
   - Tap ⚙️ Settings
   - Paste Supabase URL + Anon Key (same as root `.env`)
   - Tap `SAVE PERMANENTLY AT ROOT & GO LIVE`
   - Badge -> `● LIVE ONLINE`
   - This saves to localStorage (user override) + tries to save at root via API
   - For true permanent, rebuild APK with Supabase at root `.env` before build

## Why This is Permanent at Root Level?

- **Single source of truth:** `database/` + `data/` + `.env` at root, not inside mobile/
- **Generated from root:** `scripts/configure_root_apk.py` reads root `.env` and generates all configs at root level
- **Committed to GitHub:** `database/apk_config.json` + `mobile/src/js/root_config.js` are committed, not gitignored, so permanent in repo
- **Bundled into APK:** `build_mobile.sh` copies root configs into `dist/` which is bundled into APK assets via Capacitor
- **Hardcoded in JS:** `root_config.js` is imported in `live_db.js` as first priority, hardcoded, cannot be lost even if localStorage cleared
- **All data inside APK:** `data/mobile/` initial data copied to `dist/data/mobile/` inside APK

So when you configure data inside APK, it's configured permanently at root level (database/ + data/ + .env at root, committed to GitHub, bundled into APK).

## Troubleshooting

- **APK still offline?**
  - Did you set Supabase at root `.env` before build?
  - Run `python scripts/configure_root_apk.py --check` - is_live true?
  - Check `database/apk_config.json` has supabase_url
  - Check `mobile/src/js/root_config.js` has supabase_url hardcoded
  - Rebuild: `./scripts/build_mobile.sh` + `git push` -> new APK

- **data/ not found?**
  - Run `python scripts/configure_root_apk.py --init` to create data/ at root

- **Root configs not in dist/?**
  - Run `python scripts/configure_root_apk.py --build` first
  - Then `./scripts/build_mobile.sh` copies them to dist/

- **APK build fails?**
  - Check workflow logs: it now runs `configure_root_apk.py --build` before build
  - Ensure `mobile/src/js/root_config.js` exists (generated)
